# Curriculum Audit: KEEP, UPDATE, REDUCE, and ADD

## 1. Purpose

This audit evaluates how well the existing B.Tech CSE curriculum supports foundational learning, practical implementation, current computing tools, data-driven problem solving, and professional readiness.

Recommendations must be supported by the official curriculum, course learning outcomes, and the job-description analysis. The labels below indicate proposed directions for review, not approved changes.

## 2. Decision categories

- **KEEP:** Retain a course or learning outcome because it provides an important foundation or remains relevant.
- **UPDATE:** Retain the course but refresh its tools, examples, assessments, or learning outcomes.
- **REDUCE:** Consider reducing duplicated or lower-priority content after verifying that essential learning outcomes remain covered.
- **ADD:** Introduce a missing or insufficiently covered topic, practical module, elective, or project.

A REDUCE recommendation does not automatically mean deleting a course. A course's official status, accreditation role, and prerequisite dependencies must be checked first.

## 3. Ten recommendations

### Recommendation 1 — KEEP: Core programming and problem-solving

**Rationale:** Programming is a prerequisite for software development, automation, algorithms, databases, and applied computing. Students need to understand control flow, functions, data types, debugging, and program design before relying on higher-level tools.

**Evidence required:** Official programming-course outline, learning outcomes, and related job descriptions.

**Success indicator:** Students can implement, test, explain, and debug programs without relying entirely on generated code.

### Recommendation 2 — KEEP: Data structures and algorithms

**Rationale:** Data structures and algorithmic reasoning remain important for software efficiency, scalability, and technical problem-solving. Emerging tools do not eliminate the need to understand computational complexity and appropriate data representations.

**Evidence required:** Official course outline and technical job requirements.

**Success indicator:** Students can select appropriate data structures, analyse complexity, and justify algorithm choices.

### Recommendation 3 — UPDATE: Database and SQL practice

**Rationale:** Data-intensive roles commonly require querying, joining, aggregating, and validating structured data. Practical exercises should involve realistic datasets, data-quality checks, and query optimisation where appropriate.

**Proposed update:** Add applied SQL tasks, database design exercises, validation checks, and a small end-to-end data project if these are not already adequately covered.

**Evidence required:** Database syllabus and dated job-description requirements.

**Success indicator:** Students can write correct queries and explain the reliability of the results.

### Recommendation 4 — UPDATE: Software engineering and testing

**Rationale:** Building a working application is not sufficient if requirements, errors, access control, testing, maintainability, and documentation are ignored.

**Proposed update:** Include requirements analysis, version control, automated or structured testing, debugging, and code review in practical assessments.

**Connection to Task 1:** The campus maintenance workflow can be used to test report submission, administrative assignment, status updates, and failure handling.

**Success indicator:** Students provide reproducible tests and documented evidence of observed results.

### Recommendation 5 — UPDATE: Statistics and data analysis

**Rationale:** Data analysis requires more than producing charts. Students must understand distributions, sampling, uncertainty, correlation, and appropriate interpretation.

**Proposed update:** Include data cleaning, exploratory analysis, visualisation, statistical reasoning, and communication of limitations.

**Success indicator:** Students can explain both what the data suggests and what cannot be concluded from it.

### Recommendation 6 — UPDATE: AI-assisted learning and verification

**Rationale:** AI tools can help explain concepts and generate initial code or test ideas, but generated outputs may contain errors, unsupported claims, or insecure approaches.

**Proposed update:** Require students to document prompts, model details, outputs, independent verification, and corrections. Assessment should reward reasoning rather than unverified AI-generated answers.

**Success indicator:** Students can identify and correct errors in AI-assisted work and explain the final solution.

### Recommendation 7 — ADD: Practical data visualisation and business communication

**Rationale:** Technical findings are more useful when they are presented clearly through suitable charts, summaries, and evidence-based recommendations.

**Proposed addition:** A lab or elective covering data storytelling, dashboard design, appropriate chart selection, interpretation, and written reporting, subject to credit and curriculum rules.

**Evidence required:** Job postings that explicitly request dashboards, reporting, visualisation, or communication.

**Success indicator:** Students produce an accurate dashboard and communicate its limitations to a non-technical audience.

### Recommendation 8 — ADD: Data quality and reproducible workflows

**Rationale:** Real-world analysis depends on reliable inputs, documented transformations, reproducible results, and traceable assumptions.

**Proposed addition:** Exercises involving missing values, duplicate records, validation rules, data documentation, version control, and reproducible analysis.

**Success indicator:** Another student can follow the documented workflow and reproduce the principal results.

### Recommendation 9 — REDUCE: Verified duplication between overlapping course content

**Rationale:** Where two courses repeatedly teach the same learning outcome at a similar level, the programme may be able to reduce duplication and use the time for deeper application.

**Condition:** This recommendation can only be finalised after a course-by-course content comparison. No specific existing course is claimed to be redundant at this stage.

**Evidence required:** Course syllabi, weekly topics, learning outcomes, and assessments from the applicable batch.

**Success indicator:** Any reduction preserves required learning outcomes and prerequisite knowledge while improving progression.

### Recommendation 10 — ADD: Integrated workflow engineering capstone

**Rationale:** Students benefit from applying programming, databases, requirements analysis, testing, and reporting in a single realistic problem.

**Proposed addition:** Develop the Task 1 campus maintenance workflow into a supervised lab or capstone, with a defined problem statement, measurable requirements, test cases, and evaluation criteria.

**Success indicator:** Students demonstrate a functioning prototype, traceable tests, documentation, and a reflection on limitations.

## 4. Evidence-based finalisation

For every recommendation, complete the following record before presenting it as a final finding:

| Field | Required entry |
|---|---|
| Recommendation ID | R1–R10 |
| Category | KEEP, UPDATE, REDUCE, or ADD |
| Existing course or learning outcome | Exact official title |
| Evidence | Official syllabus section and/or job-description evidence |
| Identified gap or strength | Specific observation, not a general assumption |
| Proposed action | Concrete and feasible change |
| Credits affected | Verified credit value or pending |
| Prerequisites | Required prior knowledge or course |
| Risk or constraint | Regulation, duplication, staffing, or implementation issue |
| Success measure | Observable learning outcome |

## 5. Conclusion

The recommendations aim to preserve essential computer science foundations while strengthening practical work, data reliability, software testing, responsible AI use, and integrated projects. Final decisions depend on verification of the official curriculum, evidence of actual gaps, and the credit-balanced proposal.
